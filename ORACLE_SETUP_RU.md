# ATLAS & KOBA 4.9 — Oracle Cloud PRIVATE READY

**Единая версия для телефона и компьютера.** Сервер не создаётся автоматически. В комплекте нет секретных ключей, платных услуг или настоящей базы гостиницы.

## Почему сначала частная сеть
Для первого серверного запуска используем **Tailscale Serve**: приложение слушает только `127.0.0.1:8765`, а HTTPS-доступ разрешён только устройствам вашего tailnet. Публичные порты 8765 и 443 в Oracle **не открывать**. НЕ используйте `tailscale funnel`: это публичный интернет.

## 1. Учётная запись и восстановление
- Oracle Cloud создайте только в своём аккаунте, включите MFA (предпочтительно passkey/security key), сохраните recovery codes в менеджере паролей и резервную копию отдельно. Не пересылайте секреты в чат.
- Создайте **два аппаратных/программных способа MFA**, второй храните отдельно.
- Вы остаётесь владельцем OCI tenancy и Tailscale tailnet. Не используйте общий admin-аккаунт с подрядчиками. Минимальные роли для помощников.
- SSH: только по ключу, приватный ключ + запасной зашифрованный экземпляр храните у себя; никакого пароля SSH.
- Для ATLAS: `reset_admin_password.py` запускается **локально на сервере** от имени системного пользователя atlas после остановки сервиса; затем сервис перезапускается. Никакой публичной кнопки «забыли пароль».
- Потеря всех OCI MFA/SSH/backup может сделать восстановление невозможным; универсального мастер-ключа нет.

## 2. Oracle Always Free
В домашнем регионе выберите Ubuntu Linux ARM64 и `VM.Standard.A1.Flex` (до **2 OCPU и 12 GB RAM** для Always Free), boot volume 50 GB. Убедитесь в маркировке Always Free, не включайте платные функции и задайте бюджетные оповещения (они не являются жёстким лимитом). Бесплатные A1 могут быть недоступны или отозваны при простое.

## 3. Безопасный сервер
- Создайте обычного системного пользователя `atlas` без sudo для сервиса, каталог `/opt/atlas` для кода, `/var/lib/atlas/data` и `/var/lib/atlas/backups` для данных, права 0700. Установите Python 3, Tailscale по официальной инструкции, включите автоматические security-updates.
- Oracle NSG: не открывайте входящие 80/443/8765; SSH 22 — только со своего IP либо через OCI Bastion. Firewall ОС аналогично.
- Включите Tailscale на сервере, ноутбуке и телефоне в одном собственном tailnet; настройте MFA и доступ только своих устройств. После этого в Tailscale DNS включите MagicDNS и HTTPS certificates.
- Запишите точное имя `machine.tailnet.ts.net` (без https://) в `ATLAS_PRIVATE_HOST` в `atlas.service.example`. Запускайте приложение через systemd, привязка только к localhost:8765.
- На сервере **после установки Tailscale**: `sudo tailscale serve --bg --https=443 http://127.0.0.1:8765` (проверьте актуальный синтаксис в `tailscale serve --help`). НЕ `funnel`.
- С телефона и ноутбука: откройте `https://machine.tailnet.ts.net/login`, предварительно включив Tailscale. Первый пароль ATLAS создавайте локально на ноутбуке до переноса `auth.json` либо через SSH loopback-туннель. В приватном режиме удалённая первичная настройка запрещена.

## 4. Данные и миграция
1. **Остановить запись** в ATLAS на Windows, выполнить проверенный `EXPORT_BACKUP.bat` версии 4.8.
2. Внести копию базы на сервер по SFTP/SCP; не загружать через публичный веб-интерфейс и не присылать в чат. Проверить SHA-256 и `PRAGMA integrity_check`.
3. Разместить `atlas_data.sqlite3` и `auth.json` в `/var/lib/atlas/data/` с владельцем atlas, правами 0600. `auth.json` содержит хеш пароля, а не сам пароль. При переносе существующего пароля сброс не нужен.
4. Убедиться, что записи, планы, 49 номеров Magnolia, история и отчёты совпадают. Сначала тестировать **на обезличенной копии**.
5. На время переноса оставить Windows-приложение в режиме чтения/закрыть его: одновременная запись в две независимые SQLite базы приведёт к расхождению. После миграции **одна рабочая база на сервере**.

## 5. Резервное копирование и безопасность
- `python3 backup_server.py` создаёт целостную локальную копию SQLite и SHA-256. Это **не** защита от потери всей виртуальной машины. Автоматизируйте расписание и копирование **зашифрованных** копий во внешнее хранилище (например OCI Object Storage с отдельной политикой и сроком хранения). Тестируйте восстановление.
- Не храните в коде OCI API keys, Tailscale auth keys, recovery codes, пароли. Используйте секретное хранилище с минимальными правами.
- Не публикуйте сервер, пока не проведён аудит кода (в частности CSRF, cookie, входа и прав), проверка восстановления и тест с обезличенными данными.
- Обновления ОС, контроль логов, уведомления о недоступности, план реагирования на компрометацию — обязательны для реальной финансовой системы.

## 6. Что реализовано в 4.9
- Локальный запуск Windows остаётся, облачный режим включается только явно.
- Частный серверный режим: привязка 127.0.0.1:8765; точное имя HTTPS-хоста; `Secure` для сессионного cookie; проверка Origin для POST; пароль администратора восстанавливается **только локально**.
- Настраиваемые каталоги данных и копий, отдельная серверная копия SQLite.
- Это подготовка к пилоту, **не сертифицированный аудит безопасности и не готовый публичный хостинг**.
